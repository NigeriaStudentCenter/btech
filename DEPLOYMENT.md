# Live deployment (28 Sep 2026)

- Course site: GitHub Pages from `docs/` → https://nigeriastudentcenter.github.io/btech/start.html (the Teams link)
- Gateway: Azure API Management `btech-tutor-apim` (Consumption, rg `btech-tutor-rg`, Sweden Central)
  - API `tutor` → POST/OPTIONS `/tutor/chat`, product `btech-course`: rate-limit 60 calls/min, quota 6,000 calls/day (preflights count too)
  - Public counter key (subscription `btech-course-public`) is in `docs/config.js` as `?k=` — not a secret; regenerate in APIM + update config.js if abused
  - Adds the Function key from named value `btech-func-key` (secret)
- Function: `btech-tutor-api` (Flex Consumption, Node 22, authLevel `function` so direct calls without the gateway's key get 401; platform CORS = the Pages origin only; max 40 instances)
  - Settings: `TUTOR_ENABLED` (kill switch), `AZURE_OPENAI_ENDPOINT=https://ai-tutor-agent.services.ai.azure.com`, `AZURE_OPENAI_DEPLOYMENT=btech-tutor-gpt41mini`, `ALLOWED_ORIGINS=https://nigeriastudentcenter.github.io`
  - System-assigned identity has Cognitive Services OpenAI User on `AI-Tutor-Agent` (rg `AI`)
- Model: `btech-tutor-gpt41mini` (gpt-4.1-mini 2025-04-14, DataZoneStandard = EU data zone, 20K tokens/min hard cap)

Deploy API: `cd api && npm test && func azure functionapp publish btech-tutor-api --javascript`
Turn tutor off: `az functionapp config appsettings set -n btech-tutor-api -g btech-tutor-rg --settings TUTOR_ENABLED=false`

## Learning page "Go deeper" content
`docs/learning.html` has a "Go deeper" block in each of the 16 sections (original text and SVG diagrams).
Edit the content in `tools/deeper/section_*.py`, then run `python3 tools/build_learning.py` — it replaces the
blocks between `<!-- deeper:ID -->` markers, so it is safe to run repeatedly.

## June 2024 Unit 2 mock with automatic marking (25–26 Nov 2026)
- Web App `btech-mock-marking` (Linux B1 plan `btech-mock-plan`, rg `btech-tutor-rg`, West Europe — Sweden Central had no B1 capacity): https://btech-mock-marking.azurewebsites.net
- Serves `docs/mock-june-2024/` and `POST /api/mark` from `backend/app.py` (FastAPI). It overrides `config.js` so the page posts to `/api/mark`; the GitHub Pages copy stays without marking.
- No Microsoft sign-in (App Service Authentication is switched off). Students fill in an exam-style front cover — candidate surname, other names, 5-digit centre number, 4-digit candidate number — before the clock starts. The page saves these with the answers and puts them on downloads and prints; the service checks them, limits each candidate to 3 papers per 10 minutes and never sends them to the model. Set `CENTRE_NUMBER` to accept only your centre number.
- The Entra app registration "BTEC Unit 2 mock (centre sign-in)" and its org-wide consent are no longer used; delete them if sign-in is not coming back. Re-enabling sign-in also needs the ID-token header in `config.js` again (App Service Authentication refuses cookie-only POSTs) and `REQUIRE_SIGN_IN=true`.
- Model: same `btech-tutor-gpt41mini` deployment as the tutor (20K tokens/min shared). The Web App's system identity has Cognitive Services OpenAI User on `AI-Tutor-Agent`. One paper ≈ 7K tokens, so expect roughly 2 papers a minute; the service retries a busy model for up to 100 s.
- Limits: `MARKING_REQUESTS_PER_MINUTE` papers per minute for the whole app. `ALLOWED_ORIGINS` only accepts posts from the mock's own page. Levels-based answers (3b, 3c, 4a, 4b) and answers that try to instruct the marker are always flagged for teacher review. 1e, 2e and 2f have single right answers and are marked in code (`exact()`).
- The marking guide (question text + mark scheme) is `backend/guides/31769H-2024-06.json`. It is git-ignored because this repo is public; rebuild it with
  `python3 tools/mock_marking/build_guide.py "<June 2024 paper>.pdf" "<June 2024 mark scheme>.pdf"`.
- Deploy with one upload: `zip -qr mock-deploy.zip requirements.txt backend/app.py backend/guides/31769H-2024-06.json docs/mock-june-2024 -x '*.DS_Store'`, then
  `curl -X POST -H "Authorization: Bearer $(az account get-access-token --query accessToken -o tsv)" --data-binary @mock-deploy.zip "https://btech-mock-marking.scm.azurewebsites.net/api/zipdeploy?isAsync=true"`.
  `az webapp deploy` sometimes sends the package twice; overlapping builds fail after ~12 minutes and leave the app without `antenv` ("No module named uvicorn").
- After a deploy the app keeps serving the old build until its container restarts (Oryx packs the build into `output.tar.zst`). Check with a test paper; `az webapp restart` if needed.
- Turn marking off (the page still saves answers): `az webapp config appsettings set -g btech-tutor-rg -n btech-mock-marking --settings MARKING_ENABLED=false`
