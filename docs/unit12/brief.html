1. Assignment guide

Unit 12 is assessed by three assignments set by your teacher. This page explains what each task asks, in plain English, and what a strong answer includes. Always follow your teacher’s official brief and deadlines.

Level 1, Pass, Merit and Distinction

GradeTypical command wordsWhat the assessor looks for
Level 1Identify, produce with guidanceYou can identify the main points and complete the work with help from your teacher.
Level 2 PassExplain, describe, produce, develop, testClear explanations in your own words and complete, working evidence: a design, a program with comments, and a completed test plan.
Level 2 MeritComment on, produce a detailed…, review the extentMore depth: alternatives in your design, a fully functional program, feedback from others used to improve it, and judgements about how far it meets the requirements.
Level 2 DistinctionDiscuss, justify, refine, evaluateBalanced arguments and reasons: justify design decisions against requirements and constraints, refine code for quality, compare the final program with your design and recommend improvements.

Meet every Pass criterion first. Merit and Distinction build on the same work: they are about the quality of your thinking, not the length.

Assignment 1: Characteristics and uses of software programs

Learning aim A. You are on work experience at a software development company. Your line manager gives you two simple programs the company has written and asks you to explain how they work and comment on their quality, before you are trusted to write code for a client. Your teacher supplies the two programs and the official brief.

Hand in: A report on the two programs (with annotated code and a flowchart)

CriterionWhat the task asks (in plain English)Checklist: a strong answer…Help
1A.1 / 2A.P1Explain the purpose and characteristics of two programs
For each of the two simple programs, explain what it is for (its purpose) and its characteristics: the type of language, its inputs, processing and outputs, and the tools and techniques it uses (command words, subroutines, string handling, file handling, data structures, event handling, selection, loops, variables and data types). Level 1 (1A.1) only needs you to identify these; Level 2 Pass needs you to explain them.
  • The purpose of each program is explained in your own words
  • Inputs, processing and outputs are identified for each program
  • The type of programming language is stated (e.g. event-driven Visual Basic) with a reason
  • Each construct or technique used is named AND you explain what it does in that program
  • You refer to specific lines or parts of the code (annotated screenshots help)
  • You have run the programs (or dry-run them with a trace table) and say what happens
  • It is written in your own words

2A.M1Comment on quality, suggest improvements and draw a flowchart
Choose one of the programs and comment on its quality using the quality measures (efficiency, maintainability, portability, reliability, robustness, usability). Suggest improvements, and provide a flowchart showing how the program would process data once your improvements were made.

  • Weaknesses are identified, e.g. no validation, unclear names, repeated code, no comments
  • Each improvement is specific and linked to the weakness it fixes

Assignment 2: Design, develop and test a software program

Learning aims B and C. A client has given your company a brief describing a problem that a software program could solve, such as replacing a paper-based booking or ordering system. You will design the program, develop it in Visual Basic (or the language your teacher sets), and test and refine it. Your teacher gives you the official brief with the client’s requirements.

Hand in: Design documents, the working program (source code with comments and an executable), a completed test plan with screenshots, a feedback and changes log

CriterionWhat the task asks (in plain English)Checklist: a strong answer…Help
1B.2 / 2B.P2Describe the purpose and user requirements
Show that you understand the brief: describe the intended purpose of the program and the user requirements. Level 1 identifies them; Level 2 describes them in detail.
  • The intended purpose is described in your own words (not copied from the brief)
  • Every user requirement from the brief is listed
  • Each requirement is described: what it means and why the user needs it
  • You identify who the users are
  • It is presented clearly and professionally, as a report for the client

1B.3 / 2B.P3Produce a design for the program
Produce a design including a problem definition statement, a proposed solution (main tasks with inputs and outputs, screen layouts and navigation, algorithms in pseudocode or flowcharts, data structures and storage, validation), a list of any predefined functions/subroutines with sources, and a test plan.
  • A problem definition statement describes the current problem and how the program will solve it
  • The main program tasks are described with inputs, processing and outputs
  • Screen layouts are annotated (every control labelled with its type and purpose)
  • A navigation diagram shows how the screens link
  • Algorithms are shown as pseudocode and/or flowcharts
  • Data structures, data storage and validation are planned
  • Predefined functions/subroutines are listed with their sources
  • A test plan lists tests, test data and expected results

Hand in: A review report or presentation, with evidence from testing and feedback

For the software program, explain how the final program is suitable for the original requirements and purpose. Level 1 identifies how; Level 2 explains.

Your own work, and using AI properly

BTEC assignments must be your own work. You sign a declaration saying so. Copying from the internet, another student or an AI tool, even if you change the words, is malpractice and can mean losing the unit.

  • Allowed: asking the AI tutor or coach to explain an idea, quiz you, check what a task is asking, help you plan, or tell you what is missing from your draft.
  • Not allowed: asking any AI to write your code, pseudocode, designs, test plans or reviews, or copying AI code or wording into your work. Your program must be written by you.
  • Be open: the Assignment builder keeps an AI-use log of every question you ask the coach. Download it and hand it in, and tell your teacher how AI helped you.
  • Do not put personal details (yours or anyone else’s) into the tutor.
