Section A1 · Before the workbook

Computer parts and choosing devices

Your goal: Follow data through a computer and explain why different jobs need different hardware.

Input, processing, storage and output

Hardware is the physical equipment in a computer system. Input devices collect data: a microphone collects sound, a scanner reads an image and a sensor measures a condition. The processor follows instructions to work on that data. Storage keeps it for later. Output devices present a result or cause an action, such as a screen showing a message or a motor opening a gate. One device can do more than one job: a touchscreen is both input and output.

What is inside?

The CPU carries out instructions. RAM holds programs and data currently being used; its contents are normally lost when power is removed. An SSD or hard drive holds files between uses. The motherboard connects components. A graphics processor helps with image-related work. A network interface connects the device to a network. These parts must work together: adding a fast CPU will not fix a slow network connection.

Choose for the job

A mobile device is portable and runs from a battery. A desktop can offer a larger screen and more upgrade options. A server supports services used by other computers. A multifunction printer combines printing and scanning. Compare user needs, accessibility, performance, compatibility, power, cost and security. Include time for testing, moving files and training people.

Shared storage and recovery

NAS is storage that users reach over a network. RAID arranges several disks to improve speed or availability, depending on the level. RAID 1 mirrors data onto another disk. It can help after one disk fails, but accidental deletion can affect both copies. A separate backup, with a tested restore process, is still needed.

Worked example

A school editing computer has plenty of storage but struggles when several large programs are open. More RAM may help because more working data can stay in fast memory. First check the actual memory use; do not choose a part just because its number is bigger.

Pause and think

Why would a library kiosk need a scanner and a network connection?

Check your thinking

The scanner reads the book code. The network lets the kiosk look up or update the library record. Each part supports a different step.

A closer look inside three kinds of computer

Every computer has the same basic jobs (input, processing, storage, output), but designers package the parts very differently depending on the job. Compare the three diagrams below and look for what changes: how easy parts are to replace, how much power they use, and how much is duplicated.

A desktop PC is built from separate parts joined by the motherboard. Because the RAM, storage and graphics card sit in standard slots, a technician can upgrade or replace one part without replacing the whole computer. Laptops use similar parts, but many are soldered to the board to save space, so they are harder to upgrade.

A phone must be thin, light and last all day on a battery. Instead of many separate chips, it uses a System on a Chip (SoC) that combines the CPU cores, graphics, an AI engine and the mobile modem. Storage is NAND flash, which is non-volatile and has no moving parts. Sensors such as the accelerometer, gyroscope, GPS receiver and proximity sensor are inputs that most desktop PCs do not have.

A server provides a service to many client computers at once, so a failure affects everyone. That is why servers have lots of RAM, many CPU cores, and redundant parts: two power supplies, two network connections and drives in a RAID array, often all in a rack with an uninterruptible power supply (UPS).

Why speed depends on the slowest part

The CPU can only work on data that has been copied close to it. If data has to come from a slow hard disc or across a busy network, the fastest CPU still waits. This is called a bottleneck. When you recommend hardware, find the part that is holding the system back for that user, rather than simply choosing the biggest numbers.

Worked example: Does a faster drive matter?

  1. A video editor copies a 30 GB project (30,000 MB) to their computer.
  2. On a hard disc transferring at 150 MB/s: 30,000 ÷ 150 = 200 seconds (over 3 minutes).
  3. On an NVMe SSD transferring at 3,000 MB/s: 30,000 ÷ 3,000 = 10 seconds.
  4. For someone who opens large files many times a day, the SSD saves a lot of waiting. For someone who only writes documents, the difference is barely noticeable, so the money may be better spent elsewhere.

Always link the specification to what the user actually does.

Keeping data available: RAID and NAS

A NAS (network attached storage) is a small computer whose only job is to share its drives over a network. It usually contains two or more drives in a RAID array, so that one drive failing does not lose the files. Remember the difference: RAID keeps a system running when a disc fails; a backup lets you recover from deletion, ransomware, theft or fire.

Think it through

Why does a tablet use flash storage rather than a hard disc?

Flash has no moving parts, so it survives being dropped, uses less battery, is silent and fits in a thin case. It is also faster to access.

A shop’s till server has one power supply and one disc. Name two single points of failure and a fix for each.

The power supply (fit two redundant PSUs, plus a UPS) and the disc (use RAID 1 or RAID 5, and keep a separate backup).

A gamer buys a very powerful graphics card but keeps an old 60 Hz monitor. What limits the experience?

The monitor. It can only show 60 frames per second, so frames the card draws above that are never seen. This is a bottleneck.

In the real world: a hospital

A hospital’s patient-record servers sit in a rack with redundant power, RAID storage and a UPS backed by a generator, because doctors need the records at any hour. Nurses on wards use cheaper thin clients or tablets, because the data and processing live on the servers.

Section A2 · Before the workbook

Operating systems and programs

Your goal: Explain how an operating system connects programs, users and hardware.

The operating system is the organiser

An operating system (OS) manages resources so programs can run. Its kernel is the central part that controls important operations. It gives programs CPU time, manages memory, handles interrupts and works with device drivers. Drivers translate requests into operations a device understands. File systems organise files on storage. Privileged kernel mode lets trusted OS code perform operations that ordinary programs cannot perform directly.

Sharing and protecting resources

On a multitasking system, several tasks appear to run together because the processor switches between them or uses several cores. A multi-user OS also separates users and their permissions. A real-time OS must respond within a stated deadline; being fast on average is not enough. The OS also supports network connections and security, such as sign-in and file access rights.

Choose an interface

A graphical interface uses windows, icons and buttons. A command line uses typed instructions and can make repeated tasks easy to automate. A menu offers a limited set of choices. A ticket machine may use menus because people need a few clear options. An administrator might use commands to rename hundreds of files.

Different kinds of software

Applications help users do work, such as editing a video. Utilities maintain or protect the system, such as backup tools. Open-source licences allow access to source code under stated conditions. Open source does not automatically mean no cost, no security problems or free support. Choose software using compatibility, support, accessibility, performance and the needs of users.

Worked example

When you print a page, the application sends a request. The OS manages the print job, and a driver helps communicate with the printer. If the printer reports that it has no paper, the system must handle that event.

Pause and think

Why might a shop till use a menu instead of a full desktop?

Check your thinking

A menu can make common actions easier to find and limit mistakes. It must still support the tasks and accessibility needs of the staff.

What the operating system is really doing

The kernel is the part of the operating system that is always running. It decides which program uses the CPU next (scheduling), gives each program its own area of memory, reads and writes files through the file system, and talks to hardware through device drivers. Programs run in a restricted user mode; only the kernel runs in the privileged kernel mode, so a crashing app cannot take the whole computer down.

An interrupt is a signal that asks the CPU for attention: a key press, a network packet arriving, or a disc finishing a read. Instead of checking every device constantly, the CPU gets on with its work until an interrupt arrives. The kernel then runs the matching interrupt handler and returns to what it was doing.

Think it through

Why can a single-user multitasking OS not be used to control a car’s airbag?

It shares the CPU between many tasks and cannot guarantee how quickly it will respond. An airbag needs a real-time OS that always reacts within milliseconds.

A laptop with 4 GB of RAM becomes very slow when 20 browser tabs are open. Explain why.

The tabs need more memory than the RAM holds, so the OS keeps swapping pages to the drive. Storage is far slower than RAM, so the computer spends its time moving pages instead of working.

Give one reason a technician might prefer a command line to a GUI.

They can write a script that repeats a job, such as creating 200 user accounts, automatically and exactly the same way each time.

Section A3 · Before the workbook

Collecting and using data

Your goal: Turn collected data into useful information and plan recovery.

Collect data carefully

Hardware collects data through sensors, scanners and keyboards. Software controls forms, records readings and applies checks. Validation checks whether an input follows rules. A range check might allow an age from 0 to 120. A type check might require a whole number. These checks can reject impossible values, but cannot prove that an accepted value is true.

Six processing jobs

Sorting puts records into an order. Aggregation combines values, for example a daily total. Analysis looks for patterns or meaning. Conversion changes a representation or format. Reporting presents information for an audience. Validation checks rules. Several of these jobs may happen in one system: a shop can check prices, sort sales by date, total them and show a weekly report.

Share data between systems

Sharing can improve access and reduce repeated typing. It also creates problems: two sites may change the same record, a network may fail, or someone may receive more access than they need. Decide which system holds the main record, how updates are kept in step and who can read or change each field. Include training, cost and time when introducing the system.

Prepare for loss

A backup is a recoverable copy. An archive keeps records for longer-term reference. A recovery plan explains what to restore, where the copy is stored, who does the restore and how to check it. Test restoration: a message saying a backup finished does not prove that the files can be recovered.

Worked example

A club counts 12, 15 and 18 visitors. Aggregation gives 45 visits. Analysis could compare this with last week. A report could show a chart. A validation rule of 0–100 would accept all three counts, even if one had been typed incorrectly.

Pause and think

How would you test a backup without risking live files?

Check your thinking

Restore a sample into a separate test location, open it and compare it with the expected original. Record whether the restore worked.

Data is collected by hardware such as sensors, barcode scanners, RFID readers, card readers, cameras and keyboards, and by software such as online forms, apps that log activity, and systems that import data from other systems. Automatic collection (a sensor or scanner) is fast and avoids typing errors; manual collection (a person typing) is flexible but slower and error-prone.

  1. A school has attendance records with a tutor group, a surname and minutes late.

Section B1 · Before the workbook

Ways to build a computer system

Your goal: Compare architecture models and choose one for a situation.

Instructions are stored too

In a stored-program computer, instructions are kept in memory so the CPU can fetch them. In the simple Von Neumann model, instructions and data share memory and a transfer path. They can compete for that path. In the Harvard model, instruction and data storage have separate paths, allowing some transfers to happen at the same time. Real processors may combine ideas from both models.

Several computers working together

A cluster is a group of computers working together. It may share a large task or keep a service available when one computer fails. The computers must exchange information, which adds delay and management work. A cluster helps only if the software and task can use it well.

Where memory is matters

UMA means uniform memory access: processors have broadly similar access times to shared memory. NUMA means non-uniform memory access: a processor can access some memory faster than memory connected farther away. A program that keeps its data near the processor using it can benefit from locality.

Running an older system

Emulation makes one system behave like another. A museum may use it to run an old game. The emulator has to reproduce the behaviour expected by the program, including relevant hardware. Compatibility and performance can limit success. Choose architecture using the workload, memory access, reliability, energy and cost.

Worked example

A ticket service may divide requests across a cluster. If the database is the slow part and every request waits for it, adding more web computers may not fix the problem. Identify the bottleneck first.

Pause and think

Does a cluster always make one program run faster?

Check your thinking

No. Work must be divided effectively, and communication or shared resources can become a limit.

Two ways to connect the CPU to memory

In the stored program model, the program is held in memory just like data, so a computer can switch jobs simply by loading a different program. Early computers were rewired or re-switched for each new task. In a von Neumann machine, instructions and data share one memory and one bus, which is simple and flexible. In a Harvard machine they are separate, so the next instruction can be fetched while data is being read. Small controllers such as those in microwaves, washing machines and Arduino-style boards often use Harvard designs; modern PC processors mix both, with separate instruction and data caches in front of one main memory.

Many processors working together

A cluster links many computers, called nodes, with a fast network. Big jobs such as weather forecasting, film rendering or searching huge datasets are split into parts that run at the same time. Clusters can grow by adding nodes, and they keep working if one node fails. The cost is the network: sending data between nodes is far slower than inside one computer, so the job must split into parts that do not need to talk to each other often.

Think it through

Why do many microcontrollers use a Harvard architecture?

Their program is fixed in ROM/flash and never changes, and they need fast, predictable timing. Separate buses let an instruction and data be fetched at the same time.

A NUMA server runs slowly because one program’s data sits in another processor’s memory. Suggest a fix.

Have the operating system run the program on the processor next to its data, or move the data into that processor’s local memory.

Why is emulation usually slower than running on real hardware?

Every instruction written for the old processor has to be translated into instructions for the new one, which is extra work.

In the real world: weather forecasting

National weather services run their forecasts on supercomputers built as clusters of thousands of nodes. The atmosphere is divided into a 3D grid, and each node calculates its own region, exchanging only the edge values with its neighbours.

Section B2 · Before the workbook

How a CPU works quickly

Your goal: Trace instruction execution and explain real performance.

Fetch, decode, execute

The CPU fetches the next instruction, decodes the operation and executes it. Execution might add numbers, move data or change the next instruction address. An instruction set defines the operations the CPU understands. A program is built from these operations.

Overlap work with a pipeline

A pipeline lets different instructions occupy different stages at the same time. Instruction 2 may be fetched while instruction 1 is decoded. This can increase the number of completed instructions over time. It does not mean every instruction finishes instantly. A branch, a dependency or missing data can stall the pipeline.

Keep useful data nearby

Registers and cache provide fast storage close to the processor. A cache hit finds the requested data there. A miss requires a slower access elsewhere. Larger cache may help some workloads, but results depend on what the program accesses.

Measure the whole task

Clock speed measures cycles each second, not useful tasks finished. Instruction count, work per cycle, cache, memory and parallel software all affect speed. Multiprocessing uses several processing units. Multithreading provides several threads of execution. Mobile and embedded processors often prioritise low power, heat and predictable response. Desktop and server processors may prioritise throughput, capacity and reliability.

Worked example

With three stages and no stalls, instruction 1 uses cycles 1, 2 and 3. Instruction 2 uses cycles 2, 3 and 4. Two instructions finish after four cycles rather than six in this simplified model.

Pause and think

What happens if instruction 2 needs a result instruction 1 has not produced?

Check your thinking

It may need to wait. That dependency can cause a pipeline stall unless the processor has a way to handle it.

The instruction cycle in more detail

Every program, from a game to a spreadsheet, is turned into millions of simple machine instructions such as load a number, add, compare and jump. The list of instructions a processor understands is its instruction set. A 3 GHz clock ticks three billion times a second, so one tick lasts about 0.33 nanoseconds.

Cores, threads and cache

A multi-core processor has several complete processing units on one chip; multi-processing means using more than one of them at the same time. A program can be written as several threads, flows of work that the OS can run on different cores. Some cores can also run two threads at once, switching to the second thread whenever the first is waiting for memory. Cache keeps copies of recently used instructions and data close to the core: a cache hit is fast; a cache miss means a much slower trip to RAM.

Worked example: Why 4 cores is not 4 times faster

  1. A video export takes 12 seconds on one core. Three-quarters of the work (9 s) can be split between cores; one-quarter (3 s) must run in order.
  2. On 4 cores, the parallel part takes 9 ÷ 4 = 2.25 s, but the sequential part still takes 3 s.
  3. Total = 3 + 2.25 = 5.25 s. The speed-up is 12 ÷ 5.25 ≈ 2.3 times, not 4 times.
  4. Adding even more cores gets closer and closer to 3 s but can never beat it, because the sequential part cannot be shared.

Extra cores only speed up the part of a job that can run in parallel.

Think it through

Why might a phone run a demanding game more slowly after 10 minutes?

The chip heats up, so it lowers its clock speed (throttles) to protect itself and save battery.

Doubling the clock speed does not always halve the time a program takes. Why not?

The CPU may be waiting for memory, storage or the network. A faster clock does not make those parts faster.

Which would help a web server handling thousands of small requests more: a faster clock or more cores?

More cores, because each request is independent and can be handled in parallel.

Section B3 · Before the workbook

Tiny storage inside the CPU

Your goal: Follow the roles of registers during fetch and interrupts.

Addresses and values are different

An address identifies a memory location. A value is the data stored there. The program counter (PC) holds the address of the next instruction. The memory address register (MAR) holds the location being accessed. The memory data register (MDR) holds data travelling to or from memory.

Follow a fetch

In a simplified fetch, the PC value is copied to MAR. The instruction at that address is read into MDR and then copied into the instruction register (IR). The PC is advanced to the next instruction address according to the architecture. The CPU decodes and executes the instruction. A branch can change the next address.

Other registers

An accumulator may hold arithmetic results. General-purpose registers hold temporary values such as operands and intermediate results. Registers are tiny and fast; they are not the same as RAM. Their exact names and use vary between processor designs.

Respond to an interrupt

A device or event can request attention through an interrupt. The CPU and OS preserve enough information about the current work, run the relevant interrupt handler, then resume when appropriate. Without correct state handling, the program could continue with the wrong values.

Worked example

If PC holds 204, MAR receives address 204. Memory returns the instruction stored there through MDR to IR. The number 204 is an address; the instruction read from that address is different information.

Pause and think

Which register holds the current instruction?

Check your thinking

The instruction register, often called IR or CIR. PC holds the next instruction address.

Go deeper · B3

Where the registers sit

Registers are the fastest storage in the whole computer because they are part of the CPU itself, but there are only a few of them. General-purpose registers hold values a program is working on, such as a loop counter. Special registers have one fixed job in the instruction cycle. A 64-bit processor has 64-bit registers, so it can move or add 8 bytes in one step.

Worked example: Tracing the registers for a tiny program

  1. Memory holds: address 0 = LOAD 20, address 1 = ADD 21, address 2 = STORE 22, address 20 = 7, address 21 = 5.
  2. Fetch 1: PC = 0 is copied to the MAR. The instruction LOAD 20 arrives in the MDR, is copied to the CIR, and the PC becomes 1.
  3. Execute 1: 20 goes to the MAR, the value 7 comes back into the MDR and is copied to the ACC. ACC = 7.
  4. Fetch 2: MAR = 1, CIR = ADD 21, PC = 2. Execute 2: MAR = 21, MDR = 5, the ALU adds 7 + 5. ACC = 12.
  5. Fetch 3: MAR = 2, CIR = STORE 22, PC = 3. Execute 3: MAR = 22, MDR = 12, and 12 is written into address 22.

The PC always moves on during the fetch, before the instruction is executed.

Binary numbers

Your goal: Convert and calculate with binary, BCD and fixed-width values.

Bits and place values

A bit is 0 or 1. Eight bits form a byte. Binary place values double as you move left: 1, 2, 4, 8, 16, 32 and so on. Add the places that contain 1. For 00101101, the total is 32+8+4+1=45. State the bit width. Use kB=1000 bytes or KiB=1024 bytes when the question specifies it.

Four arithmetic operations

Addition carries when a column reaches two: 1011+0110=10001. Subtraction borrows from the next place: 1010−0011=0111. Multiplication forms shifted partial products: 11×101=1111. Division can use repeated place-value steps: 1100÷11=100. Check each result in decimal while learning.

BCD codes each decimal digit

BCD uses four bits for each decimal digit. Decimal 45 becomes 0100 0101. In BCD addition, if a digit sum is above 9 or produces a carry, add 0110 to correct the digit. For 8+7, 1000+0111=1111; adding 0110 gives 1 0101, which becomes BCD 0001 0101. For other BCD operations, work with decimal digits and valid carries/borrows, then encode each resulting digit. For example 12−5=7 is BCD 0000 0111, not an invalid four-bit digit.

Negative values and fractions

In eight-bit two’s complement, invert the bits of +5 (00000101) and add 1 to get −5 (11111011). The range is −128 to 127. Overflow happens when a result does not fit. Floating point stores a scaled number: 6.5 can be written as 1.101₂ × 2². Real formats set the mantissa and exponent widths. Finite precision means some values round; always use the format given.

Worked example

Decimal 26 = 16+8+2, so eight-bit binary is 00011010. BCD is 0010 0110 because it encodes the digits 2 and 6 separately.

Binary arithmetic

Worked example: Subtraction by adding a negative (35 − 12)

  1. Write 12 in binary: 0000 1100.
  2. Make it negative with two’s complement: flip every bit 1111 0011, then add 1 → 1111 0100 (−12).
  3. Add 35 (0010 0011) + (−12) (1111 0100) = 1 0001 0111.
  4. Throw away the carry that falls off the left of the 8 bits: 0001 0111 = 16 + 4 + 2 + 1 = 23.

Computers subtract by adding a negative number, so the same adder circuit does both jobs.

Worked example: Multiplying and dividing with shifts

  1. Shifting left one place doubles a number: 0000 0110 (6) becomes 0000 1100 (12).
  2. To multiply 6 × 5, write 5 as 4 + 1: (6 shifted left twice) + 6 = 24 + 6 = 30, which is 0001 1110.
  3. Shifting right one place halves a whole number: 0010 1100 (44) shifted right twice is 0000 1011 (11), so 44 ÷ 4 = 11.
  4. Longer divisions use the same ‘bus stop’ method as denary, but each step only asks: does it go in once, or not at all?

Negative numbers and fractions

Binary coded decimal (BCD) stores each denary digit in its own nibble. It is less efficient than pure binary but converts easily to the digits on a display, which is why calculators, digital clocks and some financial systems use it. When a BCD digit adds up to more than 9, add 0110 (6) to correct it and carry into the next digit.

Letters as numbers

Your goal: Explain character sets, code points and stored bytes.

Characters need codes

Computers store text using agreed number codes. A character set says which characters exist and how they are identified. ASCII is a limited set including Latin letters, digits and common punctuation. Seven-bit ASCII has 128 possible codes. It cannot represent every writing system.

Unicode covers more languages

Unicode assigns code points to a wide range of characters. An encoding such as UTF-8 turns those code points into stored bytes. A code point is not the same thing as a byte. In UTF-8, A occupies one byte while many other characters require more. A visible symbol can sometimes involve more than one code point.

Why this matters

A school needs names to remain correct after saving, searching and transferring records. If one system expects a different encoding, text can become unreadable or lose characters. Test inputs from several languages and check round trips: type, save, reopen, export and import.

Plan storage carefully

Do not calculate byte size by counting visible letters unless the encoding and limits justify it. Field length rules may count characters or bytes differently. Use the convention stated in an exam question.

Worked example

The code point for A is U+0041. UTF-8 stores it as one byte, 01000001. UTF-8 stores é as two bytes. That difference affects byte-size calculations.

Pictures made from pixels

Your goal: Calculate raw image size and choose suitable compression.

A raster image is a grid

A bitmap or raster picture is made of pixels. Width and height give the grid size. More pixels can show finer detail if the original image contains it. Enlarging a small image does not automatically create real detail.

Bit depth describes each pixel

Bit depth is the number of bits used per pixel in the stated format. A simple 8-bit value has 256 possible patterns. A common 24-bit colour image allocates 8 bits each to red, green and blue. Resolution and bit depth affect both quality and storage.

Calculate in clear steps

Raw pixel-data bits = width × height × bit depth. Divide by 8 for bytes. This excludes headers, metadata, padding and compression. A real saved file can therefore have a different size.

Keep the right versions

Lossless compression allows exact reconstruction. Lossy compression removes some information to save space and may cause visible artefacts. A photographer may keep a high-quality master for editing and printing, plus smaller web copies for faster loading. A vector drawing stores shapes rather than a fixed pixel grid; it can be useful for scalable diagrams, although C3 focuses on raster data.

Worked example

A 200×100 image at 8 bits per pixel uses 20,000 pixels ×8 =160,000 bits. Divide by 8 to get 20,000 bytes of raw pixel data.

Stacks, queues, arrays and lists

Your goal: Trace data structures and justify their use.

A stack reverses arrival order

A stack is last-in first-out (LIFO). Push adds to the top; pop removes from the top. A pile of trays is a useful analogy. Programs use call stacks to return from nested function calls. A full stack may overflow; trying to remove from an empty one is also an error to handle.

A queue keeps arrival order

A queue is first-in first-out (FIFO). Enqueue adds at the rear; dequeue removes from the front. Print jobs and hardware buffers often use queue behaviour. Real scheduling can add priorities, but that is an extra rule rather than ordinary FIFO.

Arrays and lists organise sequences

An array uses numbered positions, called indices. Many languages start with index 0. Arrays are useful when you need direct access by position. A list is an ordered collection; the costs of access, adding and removing depend on how the list is implemented. Do not assume all lists work the same way.

Choose by the required operations

Ask what arrives, which item must leave next, whether you need direct access and what happens when capacity is reached. The same idea may appear in software and hardware: a printer queue is managed in software, while a device buffer may also behave as a queue.

Worked example

Push A, push B, pop, push C leaves a stack with C at the top and A below. Enqueue A, enqueue B, dequeue, enqueue C leaves B at the front and C at the rear.

Grids, arrays and matrices

Your goal: Use array indices, storage order and matrix operations.

Rows, columns and dimensions

A one-dimensional array is a sequence. A two-dimensional array is a grid. Three or more dimensions can represent extra categories, such as room, day and lesson. A matrix is a rectangular grid of numbers. A two-dimensional array can store a matrix, but an array can also hold other kinds of data.

Store a grid in a line

Memory is addressed as a sequence. Row-major order stores one complete row before the next. Column-major order stores one complete column before the next. For a zero-based R×C grid, row-major offset = r×C+c. Column-major offset = c×R+r. To get a byte address, multiply the element offset by bytes per element, then add the base address.

Add and multiply matrices

To add matrices, add matching positions; their dimensions must match. Matrix multiplication takes a row from the first matrix and a column from the second, multiplies matching values and adds the products. The first matrix’s column count must match the second matrix’s row count. Swapping the order can change the result.

Transpose, transform and inverse

A transpose swaps rows and columns. Matrices can transform coordinates, such as doubling x and y. For a 2×2 matrix [[a,b],[c,d]], an inverse exists only when ad−bc is not zero. An inverse reverses the transformation; it is not generally the transpose.

Worked example

For [[1,2],[3,4]] × [[2,0],[1,2]], the top-left value is 1×2+2×1=4. The full result is [[4,4],[10,8]]. In a zero-based 3×4 array, [2,1] has row-major offset 9 and column-major offset 5.

Check your thinking

Arrays of any size

A program can calculate where any item is stored without searching. For a grid with R rows and C columns stored in row-major order, item [row][col] is at offset row × C + col. In column-major order it is at col × R + row. Multiplying the offset by the size of each item gives the byte position. Reading memory in the order it is stored is faster, because nearby items arrive in cache together.

Sending data between computers

Your goal: Describe how data travels and how it can be protected.

Describe the channel

Simplex sends one way. Half-duplex allows both ways but takes turns. Full-duplex permits both directions together. Point-to-point joins two endpoints; multi-drop shares a channel among several. Serial sends bits one after another; parallel uses several lines. Connection choices depend on distance, interference, speed, cost and mobility.

Timing and packets

Synchronous transmission coordinates timing; asynchronous transmission uses framing rather than a continuously shared clock. Packet switching divides a message into pieces. Packet information can include source, destination, sequence, payload and error-checking data. Exact fields depend on the protocol. Protocols are agreed rules for format and behaviour. A receiver may need to reorder packets and deal with missing ones.

Encryption and keys

A Caesar cipher uses a fixed alphabet shift; Vigenère uses changing shifts from a key. They teach the idea of encryption but should not protect modern sensitive records. Symmetric encryption uses a shared secret. Public-key methods use a related public/private key pair and can help establish keys or prove identity. Secure use also depends on key management, trusted endpoints and suitable protocols.

Compression is a different job

Compression reduces data size. Lossless compression preserves all the original information; lossy compression removes some. It does not make data confidential. A system may compress data and then encrypt it. Choose based on bandwidth and the cost of losing detail.

Worked example

Packets numbered 1, 3, 2 can be put back into order. A sequence number helps order them, but does not keep their contents secret. Encryption has that different role.

Section E2 · Before the workbook

Spotting errors

Your goal: Explain what error checks can and cannot detect.

What can go wrong?

Noise or faults can change transmitted bits. Error detection adds information that lets the receiver check whether data is likely to have changed. Detection does not always locate the changed bit or repair it.

Parity counts ones

With even parity, the total number of 1 bits, including the parity bit, must be even. The payload 1011001 has four ones, so add parity bit 0. One changed bit makes the count odd. Two changed bits can leave it even, so basic parity misses some error patterns.

Other checks

A checksum is a value calculated from the data and compared at the receiver. A CRC uses a polynomial-based calculation to produce a remainder and is effective against many common transmission errors. Repetition sends data again so copies can be compared. All require extra data or work, and no simple check should be described as detecting every possible error.

Respond to the result

If the check fails, the receiver needs a correction or recovery method. Depending on the system, it might request another copy or use extra information to repair the data. That is the next step, covered in E3.

Worked example

Payload 1010110 has four ones, so even parity is 0. Flip its first bit to get 0010110: now there are three ones and the check fails. Flip its second bit too to get 0110110: there are four ones and basic parity does not notice the two changes.

Pause and think

Is a checksum the same as encryption?

Check your thinking

No. A checksum helps detect change; encryption is used to protect confidentiality. They solve different problems.

Go deeper · E2

Why errors happen

Errors are more likely over long cables, weak wireless signals, near electrical machinery, or when many wires run side by side. Error detection adds a little extra data calculated from the message. The receiver repeats the calculation: if its answer is different, something changed on the way.

Worked example: Even parity, and where it fails

  1. Send the 7-bit code 1100101. It has four 1s, already even, so the parity bit is 0: 0110 0101.
  2. One bit flips to give 0110 0111: now there are five 1s, odd, so the receiver knows it is wrong.
  3. Two bits flip to give 0110 1001: four 1s, still even, so the error is not detected.
  4. Parity also cannot say which bit is wrong, so the byte must be sent again.

Worked example: A simple checksum

  1. Four bytes are sent: 45, 120, 200 and 16.
  2. Add them: 45 + 120 + 200 + 16 = 381.
  3. Keep only what fits in one byte: 381 − 256 = 125. The checksum 125 is sent after the data.
  4. The receiver adds the four bytes it received. If it also gets 125 the data is accepted; if not, it asks for it again.
  5. Weakness: if two bytes were swapped, the total would be the same and the error would be missed.

Think it through

Using odd parity, what parity bit goes with 1100110?

It has four 1s (even), so the parity bit is 1 to make five, an odd number.

Why is a CRC better than a parity bit for a 1,500-byte packet?

A parity bit only catches an odd number of flipped bits. Noise often damages several bits in a row (a burst); a CRC detects almost all bursts.

Section E3 · Before the workbook

Fixing errors

Your goal: Choose a correction method using delay and bandwidth.

Ask for another copy with ARQ

Automatic repeat request (ARQ) uses checks, acknowledgements and retransmission rules. If data is damaged or an acknowledgement does not arrive in time, a sender can resend. Sequence information helps avoid confusing repeated packets with new ones. ARQ needs a suitable return path and adds delay when retries occur.

Repair using extra data with FEC

Forward error correction (FEC) sends redundancy that allows the receiver to correct some errors. Exactly how many errors it can repair depends on the code. The receiver may not need to wait for another transmission. The extra data uses bandwidth, and decoding takes work.

Choose for the situation

A file download can often wait for a retry because an exact final file matters. A live feed over a long-delay link may benefit from FEC. The choice depends on delay, error rate, bandwidth and the importance of exact data. Some systems combine both approaches.

Avoid a common mix-up

Detection tells the system that data may be wrong. Correction or retransmission provides a way to obtain the right data. A parity check alone is not the same as a full FEC code.

Worked example

If a damaged packet needs a 600 ms round trip before a replacement arrives, a live display may show a gap. FEC might repair a small error sooner, at the cost of sending extra bits in every protected block.

Pause and think

When errors are rare and waiting is acceptable, why might ARQ be suitable?

Check your thinking

Most data arrives without extra retries, and the receiver can ask again when needed. The return delay is acceptable for that task.

Go deeper · E3

Asking again: ARQ

Automatic repeat request needs error detection (such as a CRC), acknowledgements (ACKs) and a timer. It sends as little extra data as possible, but each error costs a round trip. That is fine on a fast local network, but painful on a satellite link where each round trip takes over half a second.

Fixing it at the receiver: FEC

Real systems use cleverer forward error correction codes than simple repetition. A Hamming code mixes a few parity bits into the data so that the pattern of failed parity checks points to the exact bit that flipped, which can then be flipped back. The same idea lets RAID rebuild a lost disc, lets a scratched CD still play, and lets a QR code be read even when part of it is covered.

Think it through

Why is FEC used for live TV broadcasts?

A broadcast is one-way (simplex), so viewers’ TVs cannot ask for anything to be sent again. The TV must fix errors itself.

A download over a very noisy link keeps timing out. What is happening?

Many packets are damaged, so the sender keeps waiting for ACKs and re-sending. Adding some FEC, or fixing the cause of the noise, would reduce the repeats.

Section F1 · Before the workbook

True and false decisions

Your goal: Build truth tables and connect logic gates.

Four useful operations

AND gives 1 only when both inputs are 1. OR gives 1 when at least one input is 1. NOT reverses a value. XOR gives 1 when two inputs differ. In some notation, a dot means AND and a plus means OR. Confirm the notation and follow brackets.

Test every input combination

Two inputs have four combinations: 00, 01, 10, 11. Three inputs have eight. Add an intermediate column for each part of a longer expression. This makes errors easier to spot. For A AND NOT B, first find NOT B, then apply AND with A.

Build a circuit from an expression

For (A AND B) OR (B AND C), make two AND results and feed them into OR. B connects to both AND operations. The output is 1 for 011, 110 and 111 in A,B,C order. A wire crossing is not necessarily a connection, so show connections clearly.

Add bits with logic

A half adder adds two bits: sum = A XOR B and carry = A AND B. A full adder also accepts carry-in. Its sum is A XOR B XOR Cin. Carry-out is (A AND B) OR (Cin AND (A XOR B)). Trace all eight input combinations to check it.

Worked example

For A=1 and B=0, NOT B=1, so A AND NOT B=1. For A=1 and B=1, NOT B=0, so the result is 0.

Pause and think

What are the half-adder sum and carry for 1+1?

Check your thinking

Sum 0, carry 1. Together they represent binary 10, which is decimal 2.

Every gate at a glance

Written Boolean expressions use a dot for AND (A.B), a plus for OR (A + B), a bar over a letter for NOT (Ā) and ⊕ for XOR. You may also see ∧ for AND, ∨ for OR and ¬ for NOT. Just like in maths, brackets are worked out first, then NOT, then AND, then OR.

How a computer adds

Worked example: From a problem to a circuit

  1. An alarm (Q) should sound if the door is open (D) AND the system is armed (A), OR if the panic button (P) is pressed.
  2. Write the expression: Q = D.A + P.
  3. Circuit: D and A go into an AND gate; its output and P go into an OR gate; the OR output drives the alarm.
  4. Test some rows: D=1, A=0, P=0 gives 0 (door open, not armed: silent). D=1, A=1, P=0 gives 1. D=0, A=0, P=1 gives 1 (panic always works).

Think it through

How many rows does a truth table with 4 inputs have?

2⁴ = 16 rows.

Show how a NAND gate can act as a NOT gate.

Join both inputs together. If the input is 0, NAND(0, 0) = 1; if it is 1, NAND(1, 1) = 0, so the output is always the opposite of the input.

Simplify A.B + A.B̄.

Factor out A: A.(B + B̄) = A.1 = A. Whatever B is, the output equals A.

Section F2 · Before the workbook

Drawing how data moves

Your goal: Draw and test clear flow charts and system diagrams.

Show the order of steps

A flow chart represents a process. Use a start/end symbol, a process box for an action, an input/output symbol for reading or showing data, and a decision diamond for a question. Label the decision’s outgoing arrows, normally Yes and No. Every path should end or deliberately loop back.

Show how parts connect

A system diagram has a different focus: it shows components and the movement of data between them. A library diagram might show scanner, kiosk, network and database. Label what moves along each arrow. A box named Database alone does not explain what is read or written.

Check normal and edge cases

Walk through the diagram using sample inputs. Test values on either side of a boundary, invalid values and failures where relevant. If a score must be from 0 to 100, check validity before deciding pass or retake. State what happens next after an error.

Explain a diagram in words

Describe the order and the reason for each decision. Clear labels make the diagram easier to mark and easier for another developer to use. Do not add a branch simply to fill space: every branch must represent a rule.

Worked example

For a pass mark of 50, score 49 gives RETAKE and 50 gives PASS. Score 101 is invalid, even though it is greater than 50. That is why the range check comes first.

Pause and think

Where should an invalid score go in the flow chart?

Check your thinking

To a clearly labelled error output, followed by an explicit end or a deliberate loop back for a new input.

What is wrong with a decision diamond that has three arrows coming out, none labelled?

A decision should ask one yes/no question with exactly two exits, and each exit must be labelled so the reader knows which way to go.

In the top-up flowchart, why is 50.01 a useful test value?

It is just above the upper limit, so it checks the program uses ‘50 or less’ correctly rather than accepting anything that starts with 50.
